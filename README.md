# Merchant Portal (MP)

Портал мерчанта для приёма платежей через эквайринг MilliKart: платёжные ссылки
(Pay-by-Link, одно- и двухстадийные платежи, возвраты), справочники компаний и терминалов,
учётные записи с ролевым доступом и журнал аудита. Четыре Spring Boot-сервиса поверх общей
PostgreSQL плюс React-фронтенд.

## Модули

| Модуль | Что это | Порт |
|---|---|---|
| `common` | библиотека: security (JWT), журнал аудита, общие DTO и исключения | — |
| `auth` | вход/refresh/logout, пользователи и роли | 8081 |
| `directory` | компании, терминалы, чтение журнала аудита | 8082 |
| `pbl` | платёжные ссылки, транзакции, интеграция с TXPG | 8080 |
| `ecom` | выписка провайдера (вкладка E-commerce) и сводка главной, справочники терминалов и логинов провайдера — чтение схемы шлюза | 8083 |
| `frontend` | React + Vite + MUI | 3000 (dev) |

## Запуск

Нужны JDK 21, Node 22 LTS, PostgreSQL 16. Конфигурация — только через переменные окружения:
как минимум `DB_URL`, `DB_USERNAME`, `DB_PASSWORD` и `JWT_SECRET` (один и тот же секрет
для всех четырёх сервисов), а для `directory` и `pbl` — `CREDENTIALS_ENCRYPTION_KEY` (ключ паролей
компаний к провайдеру, одно значение на оба); шаблон — [.env.example](.env.example), полный перечень с
пояснениями — `project_docs/guides/deployment_guide.md` §20.1. Значений в репозитории нет и быть не должно.

```bash
./gradlew :auth:bootRun
./gradlew :directory:bootRun
./gradlew :pbl:bootRun
```

`ecom` нужен доступ к схеме шлюза: без `ECOM_TXPG_URL`, `ECOM_TXPG_USERNAME` и `ECOM_TXPG_PASSWORD`
он намеренно не стартует. Без `ecom` портал неполон: компанию и терминал не завести — логин компании и
терминал выбираются из справочников провайдера, которые снимает `ecom` (Р-94, Р-93), — а главная и
вкладка E-commerce пусты.

```bash
./gradlew :ecom:bootRun
```

Фронтенд:

```bash
cd frontend && npm install && npm run dev
```

Gradle-обёртка одна, в корне (`./gradlew`); модульных обёрток нет. Схему БД сервисы
накатывают сами через Liquibase, порядок старта не важен.

## Тесты

Большая часть тестов идёт на H2 в режиме совместимости с PostgreSQL. Тесты схемы, миграций
и конкурентности — на настоящей PostgreSQL в контейнере, потому что H2 в этих вопросах
эмуляция: у него нет частичных индексов, свой тип под jsonb и своя семантика блокировок.
Для них нужен **запущенный Docker**; без него они падают с «Could not find a valid Docker
environment».

```bash
./gradlew test
```

Фронтенд собирается с проверкой типов (`tsc -b` внутри):

```bash
cd frontend && npm run build
```

## Документация

Правила работы с кодом — [AGENTS.md](AGENTS.md): инварианты, безопасность, грабли и известные
ограничения, тесты. Остальные документы — в [project_docs/](project_docs/), у каждой темы одно место:

- `decisions.md` — реестр принятых решений (Р-NN).
- `plan.md` — открытые задачи.
- `guides/application_description.md` — обзор архитектуры: модули и их связи, схема БД и миграции,
  фоновые процессы, интеграция с TXPG.
- `guides/deployment_guide.md` — установка и эксплуатация, переменные окружения, nginx, systemd.
- `guides/admin_guide.md` — руководство системного администратора: компании, терминалы, пользователи и
  как база портала связана с базой провайдера.
- `guides/technical_handover.md` — технический паспорт для заказчика, словарь событий журнала аудита (§4.4).
- `modules/auth.md`, `directory.md`, `pay-by-link.md`, `ecom.md` — контракты API сервисов; Postman-коллекции
  лежат в каталогах модулей (`auth/`, `directory/`, `pbl/`, `ecom/`).
- `external/` — документы провайдера: контракт платёжного шлюза MilliKart и коллекция вызовов его API
  на тестовом стенде.
- `archive/` — история работ до 29.09.2026 (`fix_plan.md`) и код-ревью от 14.08.2026 (`code_review.md`),
  заморожены.
